## Corrections verified during completion

1. Current-detector questions exclude Dinomaly reconstruction passages. The
   project policy describes nearest-normal cosine patch distance explicitly.
2. Prior user questions help resolve follow-up topics. Stale assistant facts are
   excluded when the knowledge fingerprint changes.
3. Qwen selects a provided source-sentence ID and writes a short explanation.
   The application attaches the actual original quote and source ID, then checks
   traceability and unsupported numeric additions. This avoids depending on a
   small model reproducing long quotes and punctuation exactly. The explanation
   is generated by Qwen; it is not a deterministic answer template.
4. Conversation turns are stored atomically. Printable reports include retrieved
   source text, URLs and scope. Acknowledging an alert does not change the verdict.

## Measurement conditions and limits

Original benchmark: Python 3.12.4, torch 2.8.0+cu126, RTX 4060 Laptop GPU. The
3.11 launcher check used an existing Conda runtime and isolated compatibility
overlay. A fresh `pip install` in a new 3.11 venv was not performed.

Clean warm model medians: PCB1 54.59 ms, capsules 53.875 ms, cashew 65.615 ms;
file/decode/inference/overlay medians about 173/159/230 ms. PyTorch GPU allocated
peaks about 66/78/90 MB; other processes, driver and LLM memory are excluded.
CPU inference executed successfully, with a small expected precision difference
from CUDA/FP16. No inference score is represented as a defect probability.

The modified VisA split uses 64 normal fits, 32 distinct normal validations and
20 reassigned test anomalies per category. Remaining test images are held out.
Thresholds use validation only. Capsule pixel localization is weak; no named
defects, factory tolerances or production acceptance guarantee are established.
The optional Anomalib path, browser ONNX export and cloud integrations remain
unverified/unexecuted. No paid or public service was created.

Historical failed responses remain in the development database for audit. They
are excluded from the release archive along with all runtime history/uploads.
Citation checks provide traceability, not a mathematical proof of faithfulness.

The release candidate was CRC-checked, checked for duplicate entries, verified
against every SHA256 file entry and extracted into a new directory. Its API imports
were asserted to come from that extraction; model/embedding paths were explicitly
set to the extracted assets. No private runtime was present before the test.
The final archive retains the same runtime/model/frontend files and adds the
completed verification records and progress documentation.
